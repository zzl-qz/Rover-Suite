# S3-01：不可变处置计划契约

日期：2026-10-21（Asia/Shanghai）。本轮把已有的「灰度权重调整」待审批记录升级为可审阅、可复现、不可被原地篡改的处置计划。范围仍是单个 Admin 进程加本地 H2；没有引入 PG、多进程协作或自动写生产。

## 为什么要有计划

一张「把 v2 权重调到 20」的审批卡不足以说明该改什么、依据是什么、风险有多大，以及批准的究竟是不是后来被改过的内容。`RemediationPlan` 把这些内容冻结为一个版本：

- 资源范围和路由目标的 UID、generation、路由 revision、改前/目标权重及请求单位；
- 有序步骤、候选替代方案、已引用证据和仍未消除的假设；
- 风险等级、影响范围、动作和流量变化预算，以及容量证据是否缺失；
- 执行前的必查项、控制面回读条件、业务效果判据（若有）和补偿步骤；
- 创建时间、过期时间、超时、策略/适配器/来源版本；
- 按固定字段顺序、长度前缀和 UTF-8 编码计算的 SHA-256 `planHash`。

摘要不是展示字段：服务端重算它。计划读回、审批、修订和执行都会核对版本、摘要和动作参数；内容变一个字符，旧摘要就不再匹配。

## 当前可执行范围

目前只有一个已注册步骤：`ADJUST_ROUTE_TARGET_WEIGHT`，即在一条已绑定 UID 的路由中调整一个灰度版本权重。它使用固定适配器版本 `route-weight-v1`，风险固定为 **R2**，且必须人工批准。

首个计划不会伪造不存在的安全结论：它明确列出「剩余容量尚未获得证据确认」和「尚未配置业务恢复判据」。因此它只承诺 `CONTROL_PLANE_ONLY` 验证——资源身份、目标权重和网关应用 revision 的回读一致；这不表示错误率、延迟或用户请求已经恢复。业务效果窗口、样本量、恢复阈值、恶化护栏和缺数据处理已有类型化契约，但尚未由执行流程调度；这是 S3-05 的工作。

补偿也不是直接把整张路由表退回旧值。计划只允许逆序恢复本计划改动过的目标，并要求再次人工批准；执行前检查资源身份、当前值和本次应用后 revision，避免覆盖之后的人工或其他合法变更。

## 版本、审批和修订

创建计划时，待审批动作与计划第一版在同一事务中写入。若需要改变单位或目标值，前端调用：

```text
POST /api/agent/v1/plans/{planId}/versions
{
  "expectedVersion": 1,
  "expectedPlanHash": "<64 位小写 SHA-256>",
  "requestedValue": 20,
  "requestedUnit": "RAW_WEIGHT"
}
```

服务端重新读取当前路由并验证目标、UID、generation、revision 和改前值，再生成新的计划/动作版本；旧待审批版本标为 `SUPERSEDED`，保留在 H2 的只追加计划历史中，不能再批准。请求只允许上述四个字段，整数、范围、单位和摘要均严格校验，避免浏览器提交不明确或被悄悄扩展的执行意图。

审批请求必须携带正在看到的 `planVersion` 和 `planHash`。计划过期、摘要不一致、不是该计划最新版本、资源范围不一致或动作不受当前执行器支持，都会在写网关前拒绝。历史上没有完整计划的旧待审批卡也不能继续批准，必须重新生成。

只读 API 为：

```text
GET /api/agent/v1/plans/{planId}/versions
GET /api/agent/v1/plans/{planId}/versions/{version}
```

它们沿用工作台的登录身份和资源范围过滤；跨用户或跨环境的计划对调用方表现为不存在。创建新版本需要 `PROPOSE` 权限，并通过浏览器 CSRF 保护。

## 存储与执行边界

H2 新增迁移 v11 和 `agent_remediation_plan`。计划正文与摘要按 `(plan_id, plan_version)` 保存，且一个动作只关联一个不可变计划版本；更新执行状态不会覆盖计划历史。删除会话时，计划历史仍保留，防止审计记录被同一 ID 重用破坏。

`RouteWeightActionExecutor` 只接受这个已注册的单步计划，且在写前重新检查计划没有到期、资源 UID/generation、路由绑定、revision 和改前权重。写后控制面回读失败会如实失败；补偿只在当前 revision 仍等于本次应用 revision 时发送，防止「先改回又被别人改走」的 ABA 场景被错误地恢复。

模型仍没有写网关的权限。它能通过既有提案入口登记待审批动作，不能凭自由文本创建未知动作、绕开计划摘要，或替人批准。调查结束自动提出候选方案、细粒度策略/双人批准、异步执行、业务效果验证、生命周期去重和完整接管界面依次留在 S3-02～S3-07。

## 验收

本轮专项覆盖计划摘要稳定性与篡改拒绝、参数/单位/资源校验、旧版本 supersede、审批绑定、过期、未知适配器、H2 重启/旧库迁移、原子写入、容量上限、执行预检和补偿 ABA 防护；管理端集成测试覆盖真实认证链、角色/范围、CSRF、严格 JSON 字段和错误状态映射。

`mvn -o -pl rover-admin -am verify` 完整离线构建通过：common 20、core 129、runtime 308、admin 135，共 **592** 个 Java 测试，失败、错误和跳过均为 0；工作台脚本也通过 `node --check`。该验证证明契约和单机执行边界，不能证明业务恢复、真实生产容量或自动处置已经安全可用。
