# S2-06：模型调用账本、故障隔离与离线回放

日期：2026-10-20（Asia/Shanghai）。本轮在单 Admin + H2 中补齐模型调用追溯、供应商故障隔离与固定评测入口；沿用既有持久 Job 和预算，没有引入 PG 或多进程调度。

## 调用身份和输出判定

目标识别、主模型规划、诊断事实选择和对话工具循环，都在实际每轮请求的预算边界记录 `ModelInvocation`。它包含请求场景、客户端冻结的供应商/模型身份、端点摘要、公开配置摘要、超时与思考请求策略、输入提示和工具目录的摘要、提示词/调用策略版本、已观测证据的查询模板版本、开始/结束、核算用量和结果。任务 API 增加只读的 `modelInvocations`，工作台任务详情可展开查看。

客户端与身份在一次选择操作中取得，热更新之后已取得的旧客户端仍记旧身份。快速模型与主模型分别记录，不再用包含两台模型的展示文案代替实际调用对象。凭证和完整地址不进入公开身份；配置摘要不包含密钥，隔离用的凭证分组标识仅在进程内使用。配置成功重新应用会建立新的隔离状态。

`requestedModel` 是请求中的模型名；`returnedModel/systemFingerprint` 只在供应商实际提供时记录，否则为空。返回的名称可能仍是别名，不能据此保证远端权重不可变。没有版本信息时必须承认未知，不补造供应商版本。

传输结果和应用输出校验分别记录：`SUCCEEDED + REJECTED` 表示请求返回但 JSON、截断或引用检查没有通过；它不等于供应商断网。`ACCEPTED` 仅表示相应确定性输出契约通过，不表示业务病因被确认或修复成功；普通自由对话没有该类校验时保留 `NOT_EVALUATED`。

当前契约为 `model-policy-v2`、`target-v1`、`investigation-planning-v3`、`diagnostic-facts-v2`、`conversation-tools-v2`。提示词摘要绑定实际输入，工具摘要绑定本次目录；查询模板版本由已收集证据带入。原始提示词、日志正文、回答、响应错误正文和凭证不存入模型调用账本。

## 持久预算和恢复

调用账本与预算放在同一份 `agent_job.budget_json`，预约调用与身份、完成状态与预算结算分别一次持久化。写入失败则不发送新的模型请求，不另建一套可能与预算不一致的调用存储。

进程在请求中断时，旧的 `STARTED` 调用恢复为 `INTERRUPTED`；保留原调用数、工具数、原截止时间与已知身份。未取得完整响应的输出按剩余预留保守核算，不能靠重启获得新额度。这是本地预算估算，不是供应商账单；不能以失败时未收到文本声称费用为零。

本轮也修复输入用量校准影响输出预留的问题：供应商上报输入大于本地估算时，只追加输入核算，不能顺带减少仍可能生成的输出预留。流式部分响应后断网的测试，验证已知输入与完整输出上限被正确保留。

旧预算 JSON 没有新增字段时读为空集合。没有 Job、预算为空或旧历史任务没有调用记录时返回空列表，不伪造历史。恢复时也从已有证据重新补齐查询模板版本。没有新增数据库列或 Schema 迁移，但应用版本回退仍需排空任务并验证 JSON/枚举兼容，不能只看 Schema 是否变化。

## 供应商隔离

隔离按端点与凭证作用于任务模型调用，目标识别、规划和对话共用同组故障状态。默认连续失败 3 次打开、冷却 30 秒、最多并发 4 个请求；并发满或打开时立即返回，不排队占用更多调查线程。半开时仅一个探测，成功恢复；旧请求的迟到结果不能覆盖新一代熔断状态。不同端点/凭证不互相拖累。

配置为 `rover.agent.llm.isolation.failure-threshold/cooldown-seconds/max-concurrent`，参数越界启动失败。认证失败立即打开；429、服务端故障与网络超时等计入失败；参数错误、用户取消、预算耗尽和应用输出校验失败不当作供应商宕机。GLM/DeepSeek HTTP 边界保留状态码和有界 `Retry-After`，丢弃错误正文；较长重试间隔优先于配置冷却，最长一小时。其他 SDK 提供结构化状态时读取它，不根据异常文字猜 HTTP 状态。

打开或并发拒绝会留下零请求用量的审计记录及 `isolated` 指标；没有发出的请求不增加模型请求预算。复杂规划仍只发一次，轻量超时重试仍共用任务总预算。同步和流式 SDK 故障通过真实回环 HTTP 检查，不能在预算之外暗中重试。

规则调查继续保留证据与明确未知，对话不能在模型失败后伪造回答。已经获批的确定性权重执行不经过供应商隔离器，测试验证供应商打开时仍能完成执行及控制面回读。这里仍不代表业务恢复验证已完成。

隔离状态属于当前进程，重启后重新建立，不是跨节点熔断或持久停写开关。管理员显式测试配置用于诊断连通性，不依赖任务账本；不要把它当作普通任务路径上的模型调用。大量故障任务、长期运行与容量门禁继续在 S6 验证。

## 固定回放

数据集为 [agent-investigations-v1.json](../deploy/evals/agent-investigations-v1.json)，包含十二个场景：路由未命中、无实例、坏实例、坏版本、网关超时、容量证据不足、发布关联、多故障、数据源不可用、证据冲突、过去故障现在健康、追踪无样本。输入固定为相对运行起点的时间偏移，报告保存锚点；不读取当前环境来填充故障证据。

执行真实规划合并、调查图、只读端口、规则引用和报告代码，检查必查能力、预期假设状态、引用有效性、预算边界、模型候选必须 UNKNOWN、聚合 5xx 不归咎后端、历史窗口不被当前健康否定，以及伪造事实编号必须拒绝。源端口与规划输出是冻结脚本，既不能称为真实平台故障，也不能把通过率称为大模型根因准确率。

运行入口：

```powershell
mvn -o -pl rover-agent-runtime -am "-Dtest=FrozenInvestigationReplayTest" "-Dsurefire.failIfNoSpecifiedTests=false" test
```

报告为 `rover-agent-runtime/target/agent-evals/investigations-v1.json`，绑定数据集摘要、规划/报告提示词版本、调用策略、证据版本与遥测模板版本，并分别记录场景结果、假设、能力和调用次数。完整 `verify` 自动包含该评测；失败即构建失败。

这套回放实际找到了代码缺陷：未知假设要求补查一个已有可选能力时，规划器没有将其升级为必查，模型省略指标步骤后会漏采证据。已修复统一规划器的升级逻辑。修复前十二场景中五项失败的原报告保留在 `artifacts/agent-model-eval/s2-06-20261020/before-mandatory-promotion.json`，没有改低预期标签让评测变绿。
