# S2-04：按假设补证据的调查循环

日期：2026-10-20。部署保持单个 rover-admin + H2。本轮没有增加数据库、Agent 进程或依赖。

后续更新：本页保留 S2-04 原验收结果；规划超时与自由解读越界已继续定位和优化。最终 JAR 的八次真实 GLM 规划、四次受约束报告、工具对话及供应商失败收尾通过，详见 [模型问题定位与优化记录](agent-model-diagnostics.zh-CN.md)。受约束报告通过不等于通用自由文本或自动修复通过生产准入。

## 本轮解决的问题

以前的调查循环主要检查“规定的工具是否调用过”。一次网络失败也会让能力进入已处理集合；计划中的候选原因是文字列表，结果只有来源名称，没有具体证据引用。这会让“读过工具”和“验证了病因”混在一起。

现在每个假设保留稳定编号、状态、判断依据、支持证据 ID、反证 ID、缺失证据和下一步只读能力。结果可以合法地停在 UNKNOWN；COMPLETED 表示本次调查结束，不表示根因已确认、修复已执行或业务已恢复。

## 判断和模型的边界

- `HypothesisAssessment` 将既有 `InvestigationRules` 判定绑定到本次证据。确认必须有可用的支持引用，排除必须有反证引用。UNAVAILABLE、STALE、OUT_OF_RANGE 和其他路径的证据不能提供判定引用；没有有效引用时降为 UNKNOWN。
- H1/H3/H4/H5/H6 分别沿用路由匹配、注册实例、健康、503 样本和上游 5xx 的既有规则。H6 引用限于对应实例、足够样本的窗口证据。抽样未命中不构成反证。
- H7 用于发布或配置、实例变化相关方向。真实变更记录可以作为关联线索引用，状态仍为 UNKNOWN；BASELINE、空时间线和时间先后不能证明因果。
- 新模型格式为 `candidates: [{statement, missingEvidence, nextCapabilities}]`。模型可建议补查方向，最多六个 M 编号候选。状态由运行时强制为 UNKNOWN，不能注入 CONFIRMED 或伪造证据 ID；缺少直接验证规则的新业务病因仍须人工或后续连接器提供直接证据。旧字符串计划仍兼容。
- 模型步骤继续经过能力白名单、目标归位、只读性、步数和总预算校验。必查项由规则补齐。规划提示词包含已验证状态、实际引用和证据缺口。

## 循环、失败与恢复

1. 查询后重新评估假设；未知假设的下一步能力进入下一轮计划，而不是仅以“工具清单查完”收尾。例如追踪采不到记录后可改查历史日志、变更时间线或当前配置。
2. 明确的连接失败、网络超时及 HTTP 408/429/502/503/504 可补查一次。401/403、错误配置、解析错误、未接入、采样为空或采集关闭不会靠错误文字猜测重试；HTTP 500 不自动归为瞬态。
3. 一个能力在图内最多两次已完成尝试；正常读取完成后不因模型重复建议而重新读取。图仍执行最多三轮、十次能力调用、每轮六步。达到上限或没有新查询时保存停止原因，未验证项保持 UNKNOWN。
4. 路由瞬态失败时暂缓实例查询，路由补查成功后再决定实例范围；路由永久不可用、静态上游或非 Nameserver 发现模式继续按既有条件跳过实例。
5. `InvestigationPlan.progress` 随既有 H2 JSON 快照保存尝试结果、证据引用、事实摘要、判断边界、剩余步骤和预算计数。恢复先执行原计划的剩余步骤，不增加一轮规划、不重读成功能力、不重置补查额度。调用途中尚未完成的只读请求允许安全重做。
6. 恢复事实只保存规则需要的路由身份、服务和分组，不额外保存静态上游 URL 中的凭据。旧计划/旧报告缺少新增字段时保持空值，不补造证据关联；没有旧事实快照的旧恢复路径保持保守处理。

对话入口使用同一个假设判定契约。同一对话任务内，相同目标、参数与时间范围的成功查询直接复用证据；瞬态失败最多允许第二次读取，历史日志查询同样受限。缓存命中仍消耗原有工具循环次数额度，不能通过重复查询绕过预算。对话选工具仍由模型决定，图的自动补查调度不等于给所有闲聊自动追加调查。

工作台同时显示运行中的假设进度和最终结果，并展示引用、缺口、下一步及停止原因。外部文本继续使用 Vue 插值，不执行 HTML。

## 后续范围

S2-04 的结构化状态是诊断依据，不是自动执行授权。新业务病因仍需可验证的直接数据；模型自由文本仍须另做语义质量评测。S2-05 接入受控的 Prometheus、日志与链路读取；S2-06 继续模型版本、供应商故障隔离与离线回放；S3 才建设调查后的自动候选提案，效果验证在后续阶段。
