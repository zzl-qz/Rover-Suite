请求路径

服务登记之后，Gateway 只把流量交给还健康的实例。

  1. 登记

    Java 服务用 Starter 向 Nameserver 注册。Node.js、Python、Go、PHP、C++ 走 HTTP+JSON API。Docker 演示里 Nameserver 的 HTTP 口在 127.0.0.1:8889。

  2. 快照

    Nameserver 做健康检查，并把实例快照推给 Gateway。Gateway 记在本地缓存里，转发时不再逐次查询。

  3. 转发

    调用方访问 Gateway 127.0.0.1:8080。已支持按组发现和 targets 加权版本路由。下线实例不再接到流量。

运行时诊断

Admin 同时提供实时仪表盘和完整指标诊断。

解决问题

服务地址变化时，不再逐处修改配置。

Rover-Suite 面向多单体、旁路服务和混合语言服务逐渐变多的小团队。

服务向 Nameserver 注册。Gateway 只路由到健康实例，Nginx 与前端配置不必随后端地址逐处修改。

传统硬编码配置

  • 后端地址写在 Nginx 中
  • 地址变化后需逐处修改配置
  • 配置不感知实例健康状态

注册与发现

  • 服务自动向 Nameserver 注册
  • Gateway 通过本地实例缓存转发
  • 请求只路由到健康实例

路线图

下列能力尚未纳入当前实现。

  • 分布式追踪集成，超出 Gateway 本地请求时间线。
  • 更完整的流量治理，例如鉴权策略和分布式限流。
  • Nameserver 集群高可用，继续保持租约软状态模型。

运行边界

当前版本为 1.0.0-SNAPSHOT 单节点预览。

  • 当前版本为 1.0.0-SNAPSHOT，单节点预览。
  • Nameserver 为内存软状态，重启后由客户端重新注册。
  • 已支持按组发现和 targets 加权版本路由。group 只用来过滤路由，不是租户安全边界。
  • Gateway 不代理 WebSocket/SSE，也不终止客户端 HTTPS。发现链路依赖重新注册与查询对账恢复。
  • 默认配置适合本地或可信网络。跨出信任边界前，需收紧监听地址，并配置管理面 token 和外层 TLS/ACL。
  • Nameserver 高可用与基于持久化的恢复尚未实现。
  • SDK 产物尚未发布至 Maven Central，需从源码构建。
